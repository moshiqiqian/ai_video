# 第 2 步 · 文案

把立项结论写成能直接念的旁白。

## 输入

- `build/brief.md` 的体检结论
- `source/原文.md`（如果有）
- `project.json` 的 `target_seconds`

## 执行

先写/改 `videos/<名字>/script.txt`，然后：

```powershell
python tools\stage.py script 视频名
```

它会输出字数、预计时长、超长句，并生成 `build/script.json`（逐句清单）。

## 产出

| 文件 | 内容 |
|---|---|
| `script.txt` | 最终旁白 |
| `build/script.json` | 字数、预计秒数、逐句文本 |

## 写作要求

| 项 | 标准 |
|---|---|
| 字数 | 目标秒数 × 4.5（±10%） |
| 单句 | ≤ 40 字 |
| 标点 | 至少每两句一个句号，否则停顿切不开 |
| 数字 | 用阿拉伯数字 |
| 英文词 | 一句最多一个 |
| 括号 / 引号 | 尽量不用，部分 TTS 会念出来 |

结构（时评类）：

```
钩子（1 句）→ 事实（2-3 句）→ 解读（2-3 句）→ 观点（1-2 句）
```

## 执行后要做的

1. **全文贴给用户**，不要只说「写好了」。
2. 给出三个数字：字数、预计秒数、句子数。
3. 指出问题（超长句、和目标时长差距）。
4. 等确认：

```powershell
python tools\stage.py confirm 视频名 script
```

## 改稿流程

用户说「太长了」→ 砍 20%，重跑 `script`。
用户说「太书面」→ 拆句、换口语词，重跑。
用户说「重写」→ 换角度重写，重跑。

**每次改完都要重跑 `script` 命令**，因为 `build/script.json` 和下游的过期标记依赖它。

## 常见错误

| 报错 | 原因 |
|---|---|
| `script.txt 是空的` | 没写内容 |
| `上游「立项」还没完成` | 没跑 brief |
| `上游「立项」还没确认` | 先 `confirm 视频名 brief` |
