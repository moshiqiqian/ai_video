# 第 3 步 · 分镜

把一段文案切成 4–7 屏，每屏一个视觉重点。

## 输入

- `build/script.json` 的逐句清单
- `project.json` 的时长
- 已有的 `scenes.json`（brief 阶段生成的三屏骨架）

## 执行

```powershell
python tools\stage.py storyboard 视频名
```

它会：
1. 校验 `scenes.json`（字数、句号编号、素材引用）
2. 生成 `build/storyboard.md` 表格
3. 有错误就报错退出，不写状态

## 产出

| 文件 | 内容 |
|---|---|
| `scenes.json` | 画面结构 |
| `build/storyboard.md` | 可读的表格 |

## 先表格，后 JSON

**标准做法是先把表格给用户看**，确认后再改 `scenes.json`。

```
| 屏 | 从第几句 | 类型 | 内容 |
|----|---------|------|------|
| 1  | -       | title | 降息之后 / 三个被忽略的信号 |
| 2  | 4       | list  | 银行息差收窄 / 存款利率跟降 |
| 3  | 9       | quote | 真正的风险是没人借钱 |
| 4  | 13      | ending| 关注我，看懂财经 |
```

改一行表格 5 秒，改 JSON 要 30 秒还容易漏逗号。

## 分屏规则

| 总时长 | 屏数 | 每屏 |
|---|---|---|
| 15 秒 | 3–4 | 3–5 秒 |
| 30 秒 | 4–5 | 5–7 秒 |
| 45 秒 | 5–7 | 6–9 秒 |
| 60 秒 | 6–8 | 7–10 秒 |

硬约束（`storyboard` 会校验）：

- 标题 ≤ 16 字宽
- 清单每行 ≤ 12 字宽（英文算 0.5）
- 金句 ≤ 24 字宽
- 单屏不低于 1.5 秒
- `start_at_sentence` 必须递增且在句子总数内

## 类型搭配

不要连续两屏同类型。推荐节奏：

```
title → list → image/quote → list → ending
```

| 类型 | 用在 |
|---|---|
| `title` | 开场，或章节切换 |
| `list` | 并列要点，**最多 2 行** |
| `quote` | 观点、结论、转折 |
| `image` | 有图时插，讲结构/数据 |
| `video` | 录屏、B 站素材 |
| `ending` | 收尾，给一个动作 |

## 时间对齐

```json
{ "type": "list", "start_at_sentence": 4, "rows": ["..."] }
```

编号来自 `build/tranbuild/script.json`（渲染阶段生成）。第一次做分镜时还没有，可以先不写，等配音完成后补。

**这一步不强制要求编号**，没有编号时按平均时间切。

## 执行后要做的

1. 把表格贴给用户
2. 指出问题（行太长、类型重复、屏太短）
3. 等确认：

```powershell
python tools\stage.py confirm 视频名 storyboard
```

## 常见错误

| 报错 | 修法 |
|---|---|
| `第 2 屏第 1 行超过 12 字宽` | 缩短或拆成两行 |
| `第 1 屏标题超过 16 字宽` | 砍字 |
| `start_at_sentence=25，但只有 20 句` | 编号超出，改成 ≤ 20 |
| `分镜有错误，先改 scenes.json` | 按上面逐条改 |
